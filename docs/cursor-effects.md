# 鼠标视觉特效：移动轨迹与点击波纹

> 本文记录「把鼠标的移动轨迹与点击动作画进录像」这件事的设计取舍。
> 指针本身（形状解析、位置语义、GPU 合成）在 [`cursor-design.md`](cursor-design.md)，
> 本文只讲叠在指针之上那一层。

## 1. 要解决的问题

鼠标指针本身已经能录了。但看完自己的录屏常有这两种反馈：

- 「我刚才点了哪里？」——指针是个小箭头，点击前后画面几乎没差别；
- 「鼠标怎么飘过去的？」——没有轨迹，观众要自己一帧帧找。

所以需要两个**纯视觉**效果：点击处扩散一圈波纹、移动时留下短暂残影。

## 2. 两个效果的定义

| | 点击波纹 | 移动轨迹（流光光轨） |
|---|---|---|
| 触发 | 左键或右键**由未按到按下**的上升沿 | 指针位置相对上一采样帧发生变化 |
| 形态 | 圆环从半径 4 px 扩散到 24 px（直径 48 px），线宽 2.8→2 px（小一圈，紧凑不遮挡） | 连续流光光束（内芯高亮纯白 + 外缘青蓝霓虹发光，平滑收窄渐隐） |
| 时长 | 350 ms 线性推进，淡出用 `(1-t)^1.6` | 由调用方指定 40–3000 ms，衰减 `(1-age/life)^1.5` |
| 上限 | 同时可有很多个（连续点击各占一圈） | 最多 24 个采样点 |
| 落点 | `光标左上角 + HotSpot`（热点） | `光标左上角 + HotSpot`（紧随光标箭头尖端流出） |

初始不透明度：波纹 235/255，流光光轨最大 220/255。都不做全不透明——特效是给人看「发生了什么」，
不是用来盖住内容的。

## 3. 接口：ABI v3 的两个尾部字段

```
uint32_t cursor_click_effect;  /* 0/1：点击处画扩散圆环 */
uint32_t cursor_trail_ms;      /* 0=关闭，否则 40~3000 */
```

C# 侧只需把 `RecorderAbiVersion` 填 3，按需打开这两个字段（见
[`csharp-guide.md`](csharp-guide.md)）。校验规则：

- 两个都关 → 行为与 v2 完全一致，一个字节的额外开销都没有；
- 任一打开但 `capture_cursor == 0` → 直接报错。理由很实际：特效是画在指针之上的，
  没有指针时开特效只会得到「空的圆环」和「没有主体的残影」，与其画错不如拒绝；
- `cursor_trail_ms` 非 0 且不在 40–3000 区间 → 报错。低于 40 ms 在 30 fps 下最多
  一个采样点，等于没开；高于 3 s 则残影会跨越镜头切换，看着像画面脏了。

**为什么必须升 ABI 版本**：这两个字段追加在结构体尾部。旧宿主的结构体短一截，
Rust 侧若按新布局读尾部字段就是越界读（UB）。所以宁可明确拒绝旧版本，也不做兼容猜测。

## 4. 为什么必须在采集侧画，不能交给 UI 层

C# 小沐那一侧有 Skia，能不能在预览窗口上叠一层特效？能，但那是**预览**。
要「烧进录像文件」只有一条路：在编码前的像素上画。播放器更不可能——它不知道
指针在哪、什么时候点的。

所以特效和指针合成共用同一条通道：GPU 路径只回读一小块到 CPU、画完写回，
不破坏零拷贝。

## 5. 状态 vs 动画：最容易被忽略的架构后果

指针是**状态**：位置 + 形状，这一帧画完就结束。

特效是**动画**：波纹会自己扩张淡出、残影会随时间消失，**即使桌面和指针一动不动**。
这一点连锁影响到三个地方，漏掉任何一个都会出问题：

| 位置 | 不改的后果 |
|---|---|
| `acquire_frame` / `acquire_texture` 的「什么都没变就 `Ok(None)`」快捷路径 | 波纹只画出一帧就冻在那里，残影永远不淡 |
| 采集循环里「静止画面 → 重发上一帧」的静态分支 | 极端情况同上：DXGI 这时候根本不给新帧 |
| 采集超时（原本 50 ms） | 每个动画帧先白等 50 ms，33 ms 帧间隔被拉成 83 ms，350 ms 的波纹只剩 4 帧，看起来像闪了一下 |

对应做法：

- 采集层暴露 `overlay_animating()`，判定条件从「桌面变了 or 指针动了」变成
  「桌面变了 or 指针动了 or **特效还在动**」；
- 静态分支不再一律重发上一帧，而是让上层用缓存的纯桌面**重绘**一帧
  （CPU 路径 `recompose_overlay()`、GPU 路径 `push_overlay_frame()`）；
- 动画期间把采集超时缩到 2 ms（`ANIMATING_ACQUIRE_TIMEOUT_MS`）。
  动画一结束立刻回到 50 ms，不常驻占用。

### 5.1 为什么静态帧必须「重绘」而不是「复制」

复制上一帧的显存内容（`push_duplicate_frame`）成本为零，但它也把上一帧的
指针与特效原样搬了过去。开了叠加之后，静止画面正确的做法只有一个：
**从纯桌面副本重新派生一次，再叠加当前这一帧该有的东西**。

这也是「两份纹理」在这个需求下的额外收益：`desktop_texture` 里永远没有指针，
任何一帧都可以从它重新长出来。

## 6. 点击检测：轮询，不用钩子

| 方案 | 代价 | 问题 |
|---|---|---|
| 低级鼠标钩子 `WH_MOUSE_LL` | 需要一条带消息循环的线程；全局钩子；超时会被系统静默摘掉 | 为一个视觉特效付线程 + 生命周期管理 + 被摘掉后静默失效的风险 |
| `Raw Input` | 需要窗口句柄与消息循环 | 同上，且拿不到别的进程的输入 |
| **每帧 `GetAsyncKeyState`** | 采样率 = 帧率 | 短于一个帧间隔的极快点击会漏掉 |

人手点击的按键持续时间通常 50–200 ms，30 fps（33 ms）必然命中；60 fps 更稳。
所以选轮询：零线程、零注入、零失效模式。

初值取「都按着」（`Buttons { left: true, right: true }`）：这样程序启动时若鼠标
本来就按着，不会在第一个采样点凭空冒出一圈波纹。

## 7. 落点用热点，绘制位置不用

这是两个方向的规则，容易记反：

- **画光标**：`PointerPosition` 给的是光标图像左上角，直接用，不减 `HotSpot`
  （减了会随光标样式产生偏移，见 [`cursor-design.md`](cursor-design.md) §3）；
- **画波纹**：落点 = `光标位置 + HotSpot`。用户以为他点的是箭头尖端，不是那张
  32×32 图片的左上角。少了这一步，所有波纹都会系统性偏向左上。

## 8. 面积上限：从最旧的残影开始丢

单个光标的重绘区域是 32×32。加上轨迹后，重绘区域是「当前 + 一串历史」的并集，
而且 GPU 是按**外接矩形**回读的——斜向拖动时真实像素只有几个小块，外接矩形却
接近整屏。这是「按矩形回读」的固有代价，不是估算失误。

上限取 `max(512×512, 画面面积/4)`，取「画面面积/4」是为了让 1080p 有实际额度
（固定 512×512 在 1080p 下会频繁触顶），而 1/4 保证永远不会退化成整帧回读。

超限时的策略是**从最旧的开始丢**，不是整条丢掉：

- 最旧的残影也最淡，丢它视觉上几乎无感；
- 一刀切掉整条的现象是「快速拖动时拖尾整条突然消失」，比没有残影更显眼；
- 主光标与波纹永不丢——它们是这个特效的主体。

这条策略是单测 `oversized_plan_trims_oldest_trail_points_first` 逼出来的：
最初写的是「超限就 `trail.clear()`」，一测就发现阈值内外的行为是「有轨迹」/「没轨迹」
两个极端，中间没有过渡。

## 9. 绘制顺序：流光光轨 → 波纹 → 主光标

- 波纹压在流光光轨上：点击波纹在光束之上展开；
- 主光标压在波纹与光束上：点击时更要看清指针指到哪，光束从箭头尖端后方流出，不遮挡光标指针本身。

## 10. 圆环为什么画两层

单色圆环在某些背景上会消失：白圈落在浅色文档上看不见，黑圈落在深色终端上也看不见。

所以每个像素算两个覆盖率：`thickness/2 + 1.5` 的**深色描边**和 `thickness/2` 的
**亮色主体**，主体优先。结果是「亮环 + 深色外缘」，在明暗两种背景上都可读——
亮背景下看到的是深色外缘，暗背景下看到的是亮色主体。

边缘用 1 px 软过渡（`coverage()` 返回 0–1 的小数覆盖率）抗锯齿，使 24 px 的圆环
平滑圆润无阶梯感。

## 11. 与 GPU 路径的衔接

```text
DxgiCapture::acquire_texture()
   ├─ observe_overlay(now_us)        // 采样轨迹、检测点击上升沿（每帧都做，含超时）
   ├─ overlay.is_animating(now_us)   // 打破「没变化就返回 None」
   └─ meta.overlay = Some(OverlayPlan)

GpuSinkWriter::push_frame()
   ├─ desktop_updated ? source → desktop_texture
   ├─ CopyResource(desktop → cropped)         // 每帧从干净底重来
   └─ plan.is_empty() ? 结束 : composite_overlay(plan)
         ├─ plan.bounds() → 回读这一块到 staging
         ├─ Map → plan.draw_into() → Unmap
         └─ touched == 0 ? 不写回 : CopySubresourceRegion 写回
```

`touched == 0` 时跳过写回是实测加上去的：指针刚好完全落在画面外时，回读+绘制
什么都没改，再白搬一趟显存没有意义。

## 12. 性能

| 项 | 开销 |
|---|---|
| 每帧 `GetAsyncKeyState` × 2 | 可忽略（未开点击特效时连读都不读） |
| 轨迹采样与清理 | 最多 24 个元素的 `Vec` 操作 |
| 只有指针 | 回读 32×32 ≈ 4 KB，≈ 0.1–0.3 ms |
| 带轨迹（正常速度） | 回读几十×几十到几百×几百，≤ 1 ms |
| 带轨迹（超限） | 被裁剪回上限，最坏 = 画面面积/4 |
| 动画期间的静态帧 | 一次 `CopyResource` + 一次小回读，与「复制上一帧」同量级 |

相对 30 fps 的 33 ms 预算，常态开销在 3% 以内。

| 用例 | 覆盖 |
|---|---|
| `click_makes_one_ripple_at_hotspot_per_press` | 上升沿只触发一次、按住不重复、松手再按是新一圈、落点含热点 |
| `right_click_also_makes_a_ripple` | 右键同样算点击 |
| `disabled_click_effect_ignores_buttons` | 关闭时不产生波纹 |
| `ripple_expands_and_fades_monotonically` | 半径单调增、alpha 单调减（搞反了只有播放时才看得出来） |
| `ripple_endpoints_match_design` / `ripple_clamps_out_of_range_time` | 起止半径与超范围时间 |
| `ripple_draws_a_ring_and_leaves_the_rest` | 只画环带，圆心与远处不动 |
| `ripple_outside_frame_writes_nothing` | 越界不写、不 panic |
| `trail_alpha_decays_with_age` / `trail_records_previous_positions` | 按年龄衰减、只记走过的位置 |
| `disabled_trail_collects_nothing` | 关闭时不采样 |
| `oversized_plan_trims_oldest_trail_points_first` | 超限从最旧丢、主光标不丢 |
| `animating_while_ripple_or_trail_alive` | 动画判定（采集层依赖它出帧） |
| `bounds_is_union_and_clipped` / `empty_plan_is_detected` | 包围盒是并集且裁剪、空计划可识别 |
| `invisible_pointer_still_shows_ripple` | 指针不可见时波纹照画 |
| `gpu_cursor_is_composited_and_leaves_no_trail`（`#[ignore]`） | 显存内：位置对、无残影、不可见不画、**动画帧可重绘并抹净** |
| `e2e_gpu_recording_with_cursor_effects`（`#[ignore]`） | 真机录制：开启两个特效后帧数/时长不变（压的是动画驱动出帧这条分支） |

点击的**触发**没进 e2e：那需要在用户桌面上真的按一下鼠标，可能点到窗口或清掉文件
选择，不是测试该做的副作用。触发逻辑由上升沿单测覆盖，落笔像素由 GPU 合成单测覆盖。

## 14. 视觉验证（不是「测试过了」）

断言只能证明「某些像素变了」，证明不了「看起来对」。所以开发时用临时探针把
`draw_into` 的结果写成 BMP 看过一遍：

- 残影沿路径排列、越旧越淡、当前位置实心；
- 圆环是细环而非实心圆，明暗两种背景都能看见；
- 没有硬锯齿、没有重影错位。

这个探针只用一次就删了，不留在仓库里（保留成本高于价值，而且它输出的是人眼判据，
没法进 CI）。**注意**：探针第一次跑出来残影全空，原因是用例里造的光标形状像素
alpha 全为 0——`COLOR` 形状下 alpha=0 就是完全透明。这提醒一件事：造测试形状时
「有数据」不等于「画得出来」。

## 15. 已知边界

- **触控板/精确式触控**：`PointerPosition` 的更新粒度由系统决定，轨迹会显得跳跃；
- **极快点击**：短于一个帧间隔的按下-抬起可能整段落在两次采样之间，漏掉波纹；
- **多显示器不同 DPI**：热点是物理像素偏移，跨 DPI 移动时以 DXGI 给的坐标为准，
  不需要额外换算（这点与指针本身一致）；
- **静止画面下的动画帧率**：靠采集超时 2 ms + 帧率配速共同决定，实测 30 fps 场景
  能稳定出满帧；但在系统高负载、编码跟不上时，动画会按实际帧率降级，属于合理退化；
- **轨迹是外接矩形**：斜向快速拖动会因面积上限被裁剪，残影变短但不消失（见 §8）。
